## ビルド

```sh
sh tools/fetch-runtime.sh                                        # 一度だけ
python3 tools/make-bundle.py 4 android/app/src/main/assets/runtime
python3 tools/make-catalog.py android/app/src/main/assets/pyxel-catalog.json
cd android && ./gradlew :app:assembleRelease
```

`fetch-runtime.sh` は Pyxel の `wasm/` 一式と Pyodide の core 配布を取得し、
`pyxel.js` に4つのパッチを当てます。`make-bundle.py` はそれを1つのバンドルに
まとめ、`bundle.json` を書きます。これは OTA のマニフェストも兼ねます。
`make-catalog.py` は導入可能な Pyxel の一覧を調べて同梱します。

`minSdk` は 26、`targetSdk` は 34 です。

## 全体の組み立て

```
MainActivity            WebView と SAF のピッカー、画面まわり
 ├ PwfPathHandler       仮想 https オリジンで全バイトを配信
 ├ AppLibrary           .pyxapp・データフォルダ・セーブ・サムネイル
 ├ RuntimeStore         ランタイムのバンドルと入れ替え
 └ HostBridge           ページから呼べる唯一の窓口

web/index.html          シェル：ライブラリ、設定、プレイヤーの器
web/player.html         プレイヤー：Pyxel を載せる iframe
```

**ネットワークに出る必要がありません。** Pyodide も wheel も APK に同梱し、
`WebViewAssetLoader` の仮想オリジン `https://appassets.androidplatform.net`
から配信します。WebView が外部 URL を読み込まないことは、`JavascriptInterface`
を持つ以上ゆずれない設計線です。

`.pyxapp` の中身はバイト列として `postMessage` でプレイヤーに渡します。URL では
渡しません。CORS も `file:` スキームも関わらせないためです。

プレイヤーは1つを温存し続けます。Pyodide の起動は約7秒、`resetPyxel()` による
差し替えは 0.3 秒前後です。

## データフォルダを持つゲーム

「`.pyxapp` ＋ フォルダ」で配布されるゲームは、作業ディレクトリからそのフォルダを
読みます。SAF で選んだフォルダは**フォルダ名を接頭辞にして**取り込みます
（`LastEmulator_assets/assets/...`）。ゲーム側がその名前で探すからです。

**ファイルはコピーせず貼り付けます。** 数百 MB のフォルダを毎回 Pyodide の
メモリ上ファイルシステムに写すのは現実的ではありません。サイズだけ持った
ノードを作り、実際に読まれたときに同期 XHR で中身を取ります。Pyodide 自身の
`FS.createLazyFile` は abort するので、`FS.create` と `stream_ops` の差し替えで
手作りしています。

Pyxel は `pyxel.init()` で作業ディレクトリを展開先へ移すため、展開時にそちらへも
シンボリックリンクを張っています。コピーではなくリンクなのは、コピーすると
遅延の意味が消えるからです。

## ゲームの更新に追従する

新しいビルドは、たいてい元のフォルダに上書きされます。その都度追加し直すのは
手間なだけでなく、エントリが別物になってセーブが取り残されます。そこでファイル
から追加したエントリは、**どのドキュメントから来たか**を覚えます。

選択時に永続的な読み取り権限を取り、ライブラリを列挙するたびにサイズと更新時刻を
見て、動いていれば同じエントリに読み直します。データフォルダ・セーブ・設定は
そのままです。

つまり `id` は中身のハッシュではなく**エントリの鍵**です。代わりに `rev` を
上げ、プレイヤーは `appId` と併せて見ます。前のビルドを抱えたままのインタプリタは
「再開できる状態」ではないからです。

## フォルダから一括で取り込む

選んだフォルダの**直下だけ**を見ます。中まで降りないのは、assets フォルダが1つで
千ファイル規模だからです。assets の対応付けを名前から推測しないのも意図的で、
何と名付けるかは作者次第です。

突き合わせは URI ではなく**ドキュメント ID** で行います。同じファイルでも
「1つずつ選ぶ」経路と「フォルダ経由」では URI が別物になり、文字列で比べると
全ゲームがもう1つずつ増えます。サイズと時刻が同じファイルは読まずに飛ばします。

同じ内容を2度追加しても重複はしません（id が内容そのものだからです）。ただし
以前は既存エントリを丸ごと差し替えており、データフォルダの件数・パッドや再開の
設定・サムネイルを静かに失っていました。いまは**統合**し、これらの値はディスクの
実態から取り直します。取り込みが修復も兼ねます。

## セーブデータ

Pyodide のファイルシステムはページと一緒に消えるので、ゲームが書いたものは
外へ持ち出して戻す必要があります。

展開時に作業ディレクトリと展開先の状態を記録し、あとから現れた／サイズや時刻が
変わったファイルをゲームの書き込みとみなします。その集合をネイティブ側へ渡し
（1ファイル1呼び出し、512KB まで）、`filesDir/appsave/<id>/` に保存します。

スナップショットは集合ごと置き換えるので、**前回復元したまま触られなかった
ファイルも必ず含めます**。含めないと集合から抜け落ちます。

書き出しは zip です。ゲームが書いたファイルに加えて、**ブラウザの保存領域**も
`_pwf_webstorage.json` として同梱します。ファイルを書かず `localStorage` に
進行を置くゲームがあり、それを外した backup は彼らにとって何も守らないからです。
保存領域はゲーム単位ではなくオリジン単位なので、どの書き出しにも全ゲーム分が
入ります。

## 音はゲーム自身にやらせる

Pyxel は音声をメインスレッドで生成します。Emscripten の SDL2 が
`ScriptProcessorNode` をフレームループから回すためで、ネイティブなら専用の
オーディオスレッドが担う部分です。**メインスレッドがバッファより長く止まれば、
それはノイズとして聞こえます。**

実測（デスクトップ、5.2MB の曲）:

| | 5.2MB の曲 | 188KB の効果音 |
| --- | --- | --- |
| 同期読み込み | 約 50ms | 約 4ms |
| `pyxel.sounds[n].pcm()` のデコード | 約 180ms | 9ms |

音声の先読みを実装してみましたが、取り消しました。50ms を消して 180ms を残す
ために 71MB を常駐させていただけです。**止めているのは I/O ではなくデコードです。**

出口はそこでデコードしないことでした。自前の音声エンジンを持つゲームは
ホスト側のブリッジを探し、見つからないときだけ Pyxel の PCM に落ちます。
そこでプレイヤーが `window.PVNM_AUDIO` を提供します
（`playBgm` / `stopBgm` / `setBgmVolume` / `getBgmCurrentTime` / `isBgmPlaying` /
`playSe` / `stopAllSe`）。中身は `<audio>` 要素で、データフォルダはもともと
http で配信しているので要素をその URL に直接向けます。バイトはインタプリタを
一切通らず、デコードはブラウザ側で起きます。

> **キーの照合は `assets/` ではなく `/assets/` で。** `<game>_assets` という
> フォルダ名が前者を含むため、1階層ずれた索引ができて無音になります。

## Pyxel の PCM 音声をメインスレッドから降ろす

自前のブリッジを持たないゲームは、それでも `pyxel.sounds[n].pcm(path)` で
クリップを読みます。ゲームごとの設定（既定オフ）で、その音をページ側に回せます。

介入は、これらのゲームが実際に呼ぶものだけに絞ってあります。

- `pyxel.sounds` をプロキシに差し替え、`pcm()` はデコードせずパスだけ覚える
- `pyxel.play(ch, slot)` はその記録を見て、パスのあるスロットだけ `<audio>` で
  鳴らし、それ以外は素の Pyxel にそのまま通す
- `pyxel.stop` と `pyxel.play_pos` も同じ分岐

`play_pos` が肝です。再生中は `(スロット, 秒)`、終了後は `None` を返す必要が
あります。ゲームはそれで曲の終わりを知り、次の曲へ進みます。

> **JavaScript から返すのは `undefined` であって `null` ではありません。**
> Pyodide は `undefined` を `None` にしますが、`null` は `JsNull` という
> オブジェクトにします。これは `None` ではないので「まだ再生中」と読まれ、
> 次の `float()` が例外を投げます。しかもゲーム側が更新ループを
> `except Exception` で囲んでいると例外は握り潰され、BGM 管理が静かに停止します。

できないこと: 介入したスロットへの `total_sec` などの問い合わせは読み込まれて
いない音を答えます。`sec` のシークは Range リクエストを要しますがアセット
ハンドラは返しません。`resume` と `tick` は無視されます。だから実験的な扱いで、
だから既定はオフです。

## Web ラッパー向けに作られたゲーム

ベンダー自前の Web ページ向けに梱包されたゲームは、`js` が import できることで
「Web モード」と判定し、BGM・仮想パッドの絵柄・振動・課金をホストページに
委ねます。しかも多くを `window` から**ガードなしで**読むため、未定義はそのまま
`AttributeError` になり、タイトル画面の前で落ちます。

プレイヤーはこれらを宣言し、取り繕わずに正直な値を返します。

| フック | 返すもの |
| --- | --- |
| `isApp` | `false`（課金の仕組みは無い） |
| `playAudio` / `stopAudio` / `pauseAudio` / `resumeAudio` / `preloadAudio` | クリップごとの `<audio>` 要素。Pyodide の FS から blob 化 |
| `setVolume` / `setAudioVolume` | 要素の音量 |
| `isAudioPlaying` / `isAudioReady` / `getAudioPosition` | 要素の状態 |
| `hiddenCount` | ゲームを閉じた回数（音が切られたかの判断に毎フレーム見られる） |
| `userGestureCount` | 観測したタップとキー入力の数 |
| `vibrateDevice` | `navigator.vibrate` |
| `useVirtualGamePad` | 描画パッドが実際に画面に出ているか |
| `requestReview` / `setButtonImage` | 何もしない |
| 画面向きのロック系 | `false`（Activity のもの） |
| `setDisplayMode` | 例外を投げて「非対応」と答える（キャンバスは Pyxel のもの） |

副作用として、Web モードを体験版の判定に使っているゲームは体験版として動きます。
Pyodide 上では `js` が import できてしまうためで、これはゲーム側の線引きであり、
ランチャーが迂回すべきものではありません。

## 表示

**キャンバスは Pyxel のものです。** 整数スケール・画面モード・全画面はいずれも
Pyxel 自身がキャンバスをリサイズします。ページ側から重ねると綱引きになり、
実際に2度負けました。

ページが担保するのは1つだけ、**CSS ピクセルと端末ピクセルを一致させること**で、
Activity の `setInitialScale(100)` がそれを行います。これで Pyxel の整数倍
スケーリングがガラス上でも整数倍になります。

もう1つ、`screen.width` などは dp を返すため、Emscripten が全画面時に誤った
サイズでキャンバスを作ります。プレイヤーで `screen.*` を上書きしています。

余白の色は Pyxel の `BACKGROUND_COLOR`（`0x202224`）で、実行時 API はありません。

## ランチャーをパッドで操作する

携帯機なので、ゲームを起動するために画面へ手を伸ばすほうが不自然です。
方向キー／左スティックで移動、A で決定、B で戻る（システムの戻るボタンと同じ経路）。

移動は文書順ではなく**空間**で決めます。ライブラリは「カード＋歯車」の対が
並ぶので、文書順に辿ると誰も予測しない順路になります。規則は2つ。

- **中心ではなく辺で測る。** 1行は幅広のカードと小さな歯車で、中心で測ると
  カードは数百ピクセル先に見え、たまたま近い別物に負けます。実際は隣なのに。
- **軸が揃っているものは、揃っていないどんな近いものにも勝つ。** 揃うものが無く
  横にも近いものが無ければ動かしません。さもないと「左に何も無い」ボタンで
  左を押したとき、ページ下端の無関係なものへ飛びます。

カードは `div` なのでパッドから届かずキーボードでも押せません。`tabindex` と
`role="button"` を与えてあります。下部のバーは浮いているので、フォーカス対象には
`scroll-margin-bottom` が要ります。これがないと `scrollIntoView({block:"nearest"})`
はバーの裏に隠れた行を「見えている」と数え、末尾まで届きません。

**タップゲートもパッドで通せます。** Pyxel は `document.body` に `click` か
`touchstart` が来るまで動き出さないので、プロンプトが出ている間だけボタンや
キーの入力をその押下とみなして click を投げます。

ゲーム開始時にフレームへフォーカスを渡している点に注意してください。渡さないと、
シェル側にフォーカスの残ったカードを Enter がもう一度押してしまい、また
**ゲームパッドはフォーカスを持つ文書からしか読めない**ため、ゲートを開くはずの
ボタンをプレイヤーが見られません。

その帰結として、パッドで起動するとゲートは一度も見えません。ゲームを選んだ
ボタンがまだ押されたまま、フレームがフォーカスを得るからです。捏造した
ジェスチャではなく（ユーザーは確かに押した。届いた文書が違っただけです）、
ボタンだけを見て軸は見ていないのでドリフトでも発火しません。

## ライブラリの絵

カードは最後に遊んだ画面を映します。撮るのは**絵の無いカードだけ**です。起動の
たびに撮り直すと「6秒後にたまたま映っていたもの」になり、撮り直しボタンの仕事も
無くなります。

取得は**ネイティブ側の `PixelCopy`** です。ページから canvas を読む手は使えません。
Pyxel は WebGL で描いており、スクリプトが読める頃にはバッファは空で、しかも
ページ読み込み時に登録した rAF は Emscripten の描画より**前**に走るため、
いつまでも黒しか取れません。`preserveDrawingBuffer` を強制すれば直りますが、
フレームレートこそが問題の本体である端末でそれを削るのは筋が悪いと判断しました。

## ゲームごとに Pyxel を選ぶ

一覧はビルド時に `tools/make-catalog.py` が調査して同梱します。タグごとに
wheel の正確なファイル名・ABI・ビルド相手の Pyodide を記録するので、
一覧を見るのはオフラインで済み、取得するときだけ外に出ます。

費用は Pyodide のバージョン文字列ではなく **ABI** で決まります。バンドルと同じ
ABI（`emscripten_5_0_3` ＝ 2.9.6 以降）なら wheel と pyxel.js だけの約5MBで、
同梱インタプリタに相乗りします。それより古い版は Pyodide ごと来るので約20MB
です。Pyodide の core 配布が `tar.bz2` のみで、プラットフォームに bzip2 が
無いため commons-compress を積んでいます。

導入した版は `/runtime/<bundle>/rt-<version>/…` で解決します。その版自身の
ファイル → バンドルの Pyodide（同 ABI の層が `../pyodide` として共有する先）
→ APK が同梱する層、の3段です。

端末で導入したランタイムはビルド時のパッチ処理を通らないので、
`RuntimeStore.patchPyxelJs` が `tools/patch-pyxel-js.py` と同じ4つの書き換えを
端末側で行います。**この2つは同期させてください。**

1ページにインタプリタは1つなので、既定と違う版を指したゲームはプレイヤーの
frame を作り直します。その起動だけコールドブートになります。

## 端末上のランタイム管理

設定画面が端末上の Pyxel を一覧します。同梱分は削除できません。あとから取得した
ものには削除ボタンが付き、1回目の押下で「もう一度押すと削除」に変わります。
この WebView は `confirm()` のダイアログを出さず黙って `false` を返すので、
そのままではボタンが死にます（`prompt()` も同様に効きません）。

## ランタイムのネットワーク更新

バンドルの単位は「Pyodide ＋ wheel ＋ パッチ済み pyxel.js」です。wheel は特定の
Pyodide ABI 向けにビルドされており、混ぜると起動しません。`bundle.json` が
そのままマニフェストで、`sha256` と `size` を全ファイルぶん持ちます。

適用は staging に展開して全ファイルを検証し、`rename` で入れ替えます。**半分
適用された状態にはなりません。** 起動を確認できなかったバンドルは次回起動時に
自動で巻き戻します。

### adb で更新を試す

```sh
python3 tools/make-bundle.py 5 /tmp/ota/5
cd /tmp/ota && python3 -m http.server 8000
# 端末側の「更新元 manifest」に http://<PC の IP>:8000/5/bundle.json を入れる
```

## 次にここを触る人へ

- **`prompt()` と `confirm()` はこの WebView では機能しません。** 黙って
  `false`／`null` を返します。ページ内のダイアログか2回押しで代替してください。
- **JS から Python へ返すのは `undefined`。** `null` は `JsNull` になり `None`
  ではありません。
- **`force-stop` を使わないでください。** この機体では異常な挙動を示します。
  ホームへ出てから `am kill` で十分です。
- **レンダラの死亡はアプリのバグとは限りません。** `adb install -r` を
  繰り返すと WebView のレンダラが道連れになり、60秒に2回で WebView 自体が
  ブラックリスト入りします。
- **画面が黒いときは、まず端末が寝ていないか疑ってください。** 一度これで
  30分溶かしました。
- 変更したら実機で確かめてください。ここに書いてあることのほとんどは、
  そうやって見つかりました。
